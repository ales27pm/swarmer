# Research coverage and website capture — 2026-09-29

Status: implemented and locally verified; no deployment or iPhone qualification in this slice.

## Changed behavior

- `research.collect` accepts up to six explicit canonical public HTTPS source URLs, within the existing total page budget. These are attempted before round-robin search results, including when search fails. Document paths are not generated by the reader.
- Receipt version 1.1 records direct-source provenance and coverage: required domains without a read page, actual read domains, and search queries without a read result. The server recomputes these fields against the admitted payload. Version 1.0 remains readable.
- Direct sources cannot fabricate search snippets or search-query associations. A source supplied directly and returned by search is read once, preserving its actual search provenance.
- Actual passages are selected before the 4,000-character writer boundary. Ranking includes the focus and associated query terms, with adjacent context where space permits. HTML source line wrapping no longer splits prose into artificial passages. This lexical selection is bounded and does not prove semantic completeness.
- Dependency summaries expose coverage gaps. A completed collection describes operations, not compliance with the user's deliverable.
- Worker-card validation accepts the new bounded metadata and network declaration while preserving legacy collection-card compatibility. A coordinated server/worker rollout is still necessary before sending new fields to older workers.

## Screenshot: `no_source_pages`

The website reader called `HTTPConnection.getresponse()`. With `Connection: close`, that path released socket ownership; after the final body read, the next `settimeout()` touched a closed descriptor. The live traceback was `OSError: [Errno 9] Bad file descriptor`, surfaced as `http_unavailable`, then `robots_unavailable`, then generic `no_source_pages`.

The reader now retains socket ownership until the HTTP response body has been consumed, then closes the response and connection. A real local HTTP/1.1 server reproduces this response lifecycle. DNS restrictions, TLS checks, GET-only behavior, byte budgets and deadlines are retained.

Failed website exploration retains a private dossier with the failure receipt and preserves prior successful pages. The public error explains unavailable or disallowing robots rules when those are the recorded cause. It does not expose the private artifact path.
